# 浮窗适配与顶部播放栏

先确认背景要停在播放栏下缘，还是延伸到顶部播放栏。可导入的 `.vnplugin` v1–v3 在展开浮窗的歌词区内渲染。要让背景或动画进入顶部播放栏，按客户端内置主题制作，或者先实现并验证新的宿主接口。只有插件技能可用时，可以交付全窗设计预览与宿主接入说明，客户端实现完成后再标为可运行效果。

## 歌词区插件

- 宿主负责可用宽度、歌词区高度和裁切轮廓。以实际歌词区为构图区域，保留两侧与下方圆角的安全空间。画面铺展时填到宿主轮廓，预览按同一比例整体缩放。图稿保留可延展边缘，刘海肩部与圆角交给宿主裁切。
- VerseNotch 0.2.4 的 v3 场景标准档位如下，单位是 macOS 逻辑点。总面板宽度包含两侧肩部，实际歌词区宽度由宿主扣除肩部后确定。顶部播放栏另占高度。显示器限制了可用宽度时，按实际面板宽度重新计算场景高度。这组尺寸可用于设计和测试。

  | 面板宽度 | 场景歌词区高度 |
  | --- | --- |
  | 520 | 83 |
  | 640 | 102 |
  | 740 | 112 |

- 滚动画带的背景与前景使用相同尺寸、缩放和相位。画带按歌词区高度等比缩放并水平平铺。左右接缝在图稿中同时对齐地平线、颜色和物件轮廓，宿主绘制时将相邻图块边缘对齐到同一设备像素。
- 文字锚点要给实际字形留空间，窄档中也要容纳长歌词和双行。局部前景可以盖过字边，主要字形仍应清楚。选一条长句，让它经过靠上、靠下及临近两侧的锚点验证。
- 在实际播放浮窗至少检查 520 和 740 点两档。有条件时覆盖 640 点与外屏。对照导入预览，检查完整展开、收起途中及歌词空档，确认两侧、底部圆角和播放栏下缘没有多出的画面或空边。动态样式至少看完一轮，检查拼接、暂停、跳转与减少动态效果。

## 包含顶部的完整浮窗

- 以宿主的完整面板轮廓排版，再标出顶部播放栏、中央刘海开口、左右可用区、下方歌词区。顶部高度和中央开口来自屏幕几何。将跨区背景画成同一幅连续构图，保留顶部控件和文字需要的留白。对标题栏与歌词区分别做等比缩放容易导致交界错位。
- 先画材质与主题背景，再画必要的局部遮罩，最后由宿主绘制封面、曲名、艺人、进度与悬停按钮。顶部背景宜减少高频细节和明暗突变。以画面最亮或最复杂的一帧判断是否需要局部压暗，确保文字和控件始终清楚。
- 顶部交互由宿主负责。装饰层使用鼠标穿透，保留播放、切歌等按钮原有的点击区域、禁用状态和辅助功能标签。跨区动画使用同一个坐标系和媒体时钟，展开与收起沿用宿主轮廓和过渡进度。
- 以原生「纸上行旅」为构图参考。纸面可以连续延伸到播放栏，标题处局部压暗，播放信息保持在画面上层。客户端源码中的绘制入口、验证步骤和其他例子见下方规范。[内置歌词主题制作规范](https://github.com/MolMind/verse-notch-mac/blob/main/.agents/skills/versenotch-plugin-author/references/builtin-lyric-themes.md)
- 在最窄和最宽档验证长曲名、无封面、播放及暂停、悬停按钮出现与消失、展开与收起、减少动态效果，以及样式透明度归零。检查按钮能实际操作，中央刘海开口与面板轮廓仍由宿主管理。支持无刘海或外接显示器时，使用实际布局再验收一遍。
