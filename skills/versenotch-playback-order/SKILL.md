# 设计播放顺序

播放顺序插件契约尚未开放。交付规则提案和有确定预期的队列样例。宿主负责解析、播放与手动操作，规则只返回候选排序或下一首候选。

1. 定义输入范围、稳定曲目标识、可用属性和缺失值处理。列出候选过滤、分组、权重、排序、近期防重复和同分处理的执行顺序。
2. 明确当前曲目、手动指定下一首、跳过、单曲循环和队列更改的优先关系。宿主先处理用户明确的队列操作，再对符合条件的曲目应用规则。
3. 使用随机时固定种子来源、候选排序起点与同种子复现预期。写明输入规模、时间预算和宿主回退。分别处理全被过滤、无可播放项与超时。

## 交付

用伪代码或规则表表达算法。每个样例列出原队列、当前曲目、近期历史、固定种子（如有）、手动操作和期望排序。例如队列为 A、B、C，当前 A，最近播放 B，规则跳过当前与最近一首时，下一首是 C。

至少覆盖空队列、同名不同 ID、真正重复项、同权重、手动跳过、用户指定下一首、未知标签和队列中途变化。
