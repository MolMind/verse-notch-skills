# 设计平台登录接入

为每个服务单独交付一份 Markdown 提案。平台登录契约和市场安装尚未开放，交付物用于评审和宿主开发。

1. 确认目标平台及所需能力。区分登录、只读歌单、公开搜索和播放，逐项核对官方文档、服务条款和接入授权。记录文档版本或核对日期，区分已证实、待验证和不支持的能力。
2. 描述授权开始、等待用户、成功、取消、超时、过期和撤销。说明凭证归属、钥匙串存储、退出后的处理及权限扩大时的重新授权。使用示例账号和占位凭证。缺乏正式接入依据时将能力列为待开放。
3. 为每项能力列出所需域名、接收方、用途和最少请求字段。区分登录和内容授权，保留服务对播放、地区和试听范围的限制。歌词或封面缺失交由独立补全能力处理。
4. 定义平台 ID、宿主模型映射和错误回退。停用时取消该平台的请求，阻止迟到回包写入，其他平台、本地与自建来源继续可用。

## 交付

使用「平台与用途」「能力及授权依据」「登录与凭证生命周期」「域名、请求数据与宿主接入点」「验收与待补依赖」组织提案。验收至少覆盖成功授权、过期重登、用户取消、停用后迟到响应和来源隔离。多个平台分别输出，保留独立授权记录。
